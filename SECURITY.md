# Security policy

## Supported versions

Security fixes are applied to the latest tagged minor release and the default
branch.

## Reporting a vulnerability or accidental disclosure

Do not open a public issue for credentials, private infrastructure details,
proprietary identifiers, or confidential files. Use GitHub's private security
advisory feature after publication, or contact the maintainer through the
private channel listed in the repository profile.

Include affected versions, impact, reproduction steps, and suggested
mitigation when safe to do so. Maintainers should acknowledge a report within
seven days and coordinate disclosure after a fix is available.

The automated public-release audit is defense in depth. It is not a guarantee
that a repository contains no confidential or security-sensitive material.
