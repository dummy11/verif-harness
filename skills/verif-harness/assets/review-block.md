# Review Block Templates

Every doc listed in `.harness-config.json` REQUIRED_DOCS must end with the
review sections below. `.harness/check_ai_workflow.py` enforces heading
spelling and internal consistency (Lifecycle ↔ Review Metadata ↔ Approval
Decision ↔ Review Trace).

Do NOT modify heading spelling — the check script pattern-matches them.

Four review states are supported: **Draft/Pending** → **Approved** →
**Living** (variant of Approved for growth docs) → **Frozen**. Use the
matching block for the current state. `stage_review_packet_template.md`
+ `batch_upgrade_stage.py` help transition all docs in a stage in bulk.

---

## Template 1: Draft / Pending (initial state)

Use this for a freshly generated doc that has not been reviewed yet.

```markdown
## Lifecycle

Status: Draft
Baseline: Pre-Stage 0
Frozen Sections:

- None

Mutable Sections:

- All

## Review Trace

### Review Pending

Reviewer: Human
Status: Pending

Findings:

- Initial draft awaiting Stage 0 baseline review.

Required Changes:

- Pending human review.

Resolution:

- Pending human review.

## Revision Log

- <YYYY-MM-DD>: Initial draft generated by verif-harness skill.

## File-Level Human Review

### Project-Level References

- `<path/to/related-doc.md>`

### Review Metadata

- Status: Pending
- Reviewer: Human
- Decision Date: TBD

### Human Decisions

- Pending human review.

### Human Review Notes

- None

### Approval Decision

Pending human review.
```

## Template 2: Approved (architecture baseline)

Use for docs whose content is frozen at Stage N approval (architecture
docs like `verification_workflow.md`, `verification_plan.md`,
`tb_architecture.md`, `plan.md`, `roadmap.md`, `assertion_plan.md`,
`harness_style_methodology.md`, `AGENTS.md`). Post-approval changes to
`Frozen Sections` require change request.

```markdown
## Lifecycle

Status: Approved
Baseline: Stage <N> approved
Frozen Sections:

- Human Decisions
- Approval Decision

Mutable Sections:

- 暂定决策 (Provisional)
- 开放问题
- Revision Log
- Review Trace
- Human Review Notes

## Review Trace

### Approved <YYYY-MM-DD>

Reviewer: Human
Status: Approved

Findings:

- Baseline reviewed via `stage<N>_review_packet.md`; all Human Decisions
  approved; Provisional decisions accepted for Stage gate revisit; open
  questions tracked to external dependencies.

Required Changes:

- None. Provisional revisits scheduled per `roadmap.md § Stage Entry Gate
  Re-review`.

Resolution:

- Baseline approved as part of Stage <N> doc set on <YYYY-MM-DD>.

## Revision Log

- <prior entries kept>
- <YYYY-MM-DD> (Stage <N> baseline approved): reviewed by Human against
  stage<N>_review_packet.md; all Human Decisions accepted; Provisional
  decisions kept for Stage gate revisit; open questions tracked.

## File-Level Human Review

### Project-Level References

- `<path/to/related-doc.md>`

### Review Metadata

- Status: Approved
- Reviewer: Human
- Decision Date: <YYYY-MM-DD>

### Human Decisions

- **HD-1** <decision text>
- **HD-2** <decision text>
- ...

### Human Review Notes

- None

### Approval Decision

Approved as part of Stage <N> baseline on <YYYY-MM-DD>.
```

## Template 3: Living (growth docs)

Use for docs expected to grow through Stage 3+ (coverage_plan,
testcase_list, feature_matrix, reference_model_spec). Body content is
Mutable — increments during Stage progression need only a Revision Log
entry, no change request. `Frozen Sections` items still need CR.

```markdown
## Lifecycle

Status: Living
Baseline: Stage <N> living
Frozen Sections:

- Human Decisions
- Approval Decision

Mutable Sections:

- Body content (随 Stage 演进增长)
- 暂定决策 (Provisional)
- 开放问题
- Revision Log
- Review Trace
- Human Review Notes

## Review Trace

### Approved <YYYY-MM-DD>

Reviewer: Human
Status: Approved

Findings:

- Baseline reviewed; content marked Living to accommodate Stage-driven
  updates.

Required Changes:

- None. Body content evolves without change request; only Frozen Sections
  require CR.

Resolution:

- Baseline approved as Living on <YYYY-MM-DD>.

<... other sections identical to Approved template, except Approval
Decision text ...>

### Approval Decision

Approved as part of Stage <N> baseline on <YYYY-MM-DD> (Living).
```

Note: Review Metadata Status = `Approved` for Living docs (check script
does not recognize `Living` as a review status; it is only a Lifecycle
value).

## Template 4: Frozen (locked baseline)

Use only when project team explicitly locks a doc against any changes.
Rare in practice — most docs stay Approved / Living to allow revision log
appends.

```markdown
## Lifecycle

Status: Frozen
Baseline: Stage <N> frozen
Frozen Sections:

- <all sections that must not change>

Mutable Sections:

- Revision Log (append only)

## Review Trace

### Frozen <YYYY-MM-DD>

Reviewer: Human
Status: Frozen

<...>

### Review Metadata

- Status: Frozen
- Reviewer: Human
- Decision Date: <YYYY-MM-DD>
```

## Status transitions

| Review Metadata Status | Lifecycle Status | Approval Decision must contain | Review Trace latest Status |
|-----------------------|-----------------|-------------------------------|---------------------------|
| Pending | Draft (or Living for pre-baselined) | "pending" | Pending |
| Changes requested | Draft | (not "approved") | Changes requested |
| Approved | Approved | "approved" (not "pending") | Approved |
| Approved | Living | "approved" (not "pending") | Approved |
| Frozen | Frozen | "approved" (typically "Frozen as part of ...") | Frozen |

The check script (`check_ai_workflow.py`) rejects mismatched combinations.
If you change one field, update all four. `batch_upgrade_stage.py`
automates this transition for a full stage doc set.

---

## Sections a doc must include (regardless of state)

- `## Lifecycle`
- `## Review Trace`
- `## Revision Log`
- `## File-Level Human Review`
- `### Project-Level References` (nested under File-Level Human Review)
- `### Review Metadata`
- `### Human Decisions`
- `### Human Review Notes`
- `### Approval Decision`

Additionally, per `doc-conventions.md § 决策生命周期约定`, every doc has:

- `## 暂定决策 (Provisional)` — with `- None` if empty
- `## 开放问题` — with `- None` if empty
